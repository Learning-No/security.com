Trust boundaries
Internet → edge: Treat all inbound traffic as untrusted; validate and filter.
Edge → application: Enforce identity, authorisation, and API policy.
Workload → data: Use workload identity and narrowly scoped permissions.
Production → operations: Separate privileged administration and audit access.

Threat modelling workflow
01 · Scope
Define system purpose, users, dependencies, and security objectives.
02 · Decompose
Draw processes, data stores, data flows, and trust boundaries.
03 · Identify threats
Use STRIDE to review spoofing, tampering, repudiation, disclosure, denial of service, and elevation of privilege.
04 · Assess risk
Estimate likelihood, impact, exposure, and existing safeguards.
05 · Treat and validate
Assign mitigations, owners, evidence, and review dates.

STRIDE review prompts

S · Spoofing

Can an identity or service be impersonated? Review MFA, certificates, and workload identity.

T · Tampering

Can data or configuration be changed without authorisation? Review integrity and change control.

R · Repudiation

Can an action be denied? Review attributable, protected audit records.

I · Information disclosure

Can sensitive data be exposed? Review access, encryption, and data flows.

D · Denial of service

Can availability be disrupted? Review capacity, rate limits, and resilience.

E · Elevation of privilege

Can a user gain excess permissions? Review authorisation and privilege boundaries.

Controls library

Baseline security control families and the evidence that demonstrates operation.

Identity & access
MFA: Require phishing-resistant MFA for privileged and sensitive access where feasible.
Least privilege: Use role-based access, scoped permissions, and periodic access reviews.
PAM: Control privileged sessions, approvals, and credential rotation.
Lifecycle: Automate joiner, mover, and leaver access changes.
Network & infrastructure
Segmentation: Separate user, application, data, management, and production zones.
Secure configuration: Apply hardened baselines and configuration drift checks.
Exposure management: Inventory assets and prioritise remediation by risk.
Resilience: Protect backups and test recovery procedures.
Application & data
Secure SDLC: Threat model, review code, scan dependencies, and test before release.
API security: Enforce authentication, object-level authorisation, validation, and rate limits.
Encryption: Protect data in transit and at rest with managed keys.
Secrets: Keep secrets out of source code and rotate them through a vault.
Detection & governance
Logging: Collect time-synchronised security events with controlled retention.
Detection: Map use cases to threats and test alert quality.
Incident response: Define roles, escalation, evidence handling, and exercises.
Assurance: Track exceptions, owners, evidence, and review dates.
